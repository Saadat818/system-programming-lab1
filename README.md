# Лабораторная работа 1: файлы и каталоги

Собственный пример для среднего уровня. Структура выдаётся преподавателем на занятии, поэтому при необходимости имена, размеры и расположение нужно изменить под полученный вариант.

```text
StudyLab/
├── notes/
│   ├── topic.txt       текст «System programming» и перевод строки
│   └── empty.txt       пустой файл
├── data/
│   ├── random.bin      128 случайных байт
│   └── zeros.bin       64 нулевых байта
├── archive/
│   └── topic_copy.txt  жёсткая ссылка на notes/topic.txt
└── notes_link          символьная ссылка на notes
```

## Запуск

В терминале перейдите в папку с файлами. Для программы C++:

```sh
g++ -std=c++17 -Wall -Wextra create.cpp -o create_lab
g++ -std=c++17 -Wall -Wextra delete.cpp -o delete_lab
./create_lab
ls -liR StudyLab
./delete_lab
```

Для скрипта, после удаления структуры:

```sh
sh create.sh
ls -liR StudyLab
./delete_lab
```

Оба способа создают одинаковую структуру и размеры; случайные данные при запусках различаются. Программа и скрипт намеренно останавливаются, если каталог StudyLab уже существует. Программа удаления рассчитана только на эту конкретную структуру и удаляет сначала файлы и ссылки, затем пустые каталоги; если добавить другие файлы, удаление каталога завершится ошибкой.

## Как объяснить

* `mkdir` создаёт каталоги. `open` создаёт файлы и возвращает их дескрипторы; `write` записывает текст и данные, `close` закрывает файлы.
* `read` получает случайные байты из `/dev/urandom`; `ftruncate` увеличивает пустой файл до 64 байт, заполненных нулями.
* Жёсткая ссылка — ещё одно имя тех же данных: у двух имён общий inode. Символьная ссылка хранит путь к каталогу.
* `unlink` удаляет имя файла или символьную ссылку, `rmdir` удаляет пустой каталог. В выводе `ls -liR` можно сравнить номера inode жёстких ссылок и увидеть символьную ссылку.
